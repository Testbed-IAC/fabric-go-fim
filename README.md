# fabric-go-fim

`fabric-go-fim` is a Go implementation of the FABRIC ASM/FIM topology
construction layer.

The repository provides Go APIs for building FABRIC experiment topologies,
serializing them to GraphML, loading existing GraphML, validating catalog-backed
components, and comparing topology intent for drift.

This is intended to be useful to the FABRIC community as a Go library and as a
foundation for a future Terraform provider. It is not a Terraform provider
itself.

## What It Does

- Builds FABRIC ASM topology graphs in Go.
- Serializes and loads FABRIC-compatible GraphML.
- Preserves semantic parity with Python FIM fixtures.
- Derives deterministic IDs for repeatable topology output.
- Uses embedded FABRIC instance and component catalogs.
- Generates component subtrees from catalog data.
- Compares topology intent while ignoring runtime-only FABRIC metadata.

## Where Things Live

```text
pkg/topology   primary topology construction and GraphML API
pkg/catalog    embedded FABRIC catalog data and lookup APIs
pkg/sliver     typed ASM/FIM records, enums, and property encoding
pkg/diff       semantic graph normalization and drift comparison
pkg/fim        FIM compatibility metadata

internal/graph    graph implementation details
internal/graphml  GraphML XML reader/writer details

examples/         small runnable examples
testdata/fixtures Python FIM parity fixtures
```

Start with [pkg/topology](pkg/topology/README.md) if you want to build or load a
topology. Use [pkg/catalog](pkg/catalog/README.md) for instance and component
catalog lookups. The other package READMEs describe their exposed API and
ownership.

## Relationship To Python FIM

Python FIM remains the behavioral reference for topology semantics. This module
does not call Python at runtime, but tests compare Go-generated topologies
against GraphML fixtures generated by Python FIM.

The comparison is semantic rather than byte-for-byte. UUIDs, XML ordering, and
JSON key ordering may differ while still representing the same topology.

## Terraform Provider Direction

A future Terraform provider should primarily use `pkg/topology`, with
`pkg/catalog` and `pkg/sliver` for schema conversion and validation.

Provider code should not import `internal/graph` or `internal/graphml`.

## Catalog Data

Catalog JSON is embedded from:

- `pkg/catalog/data/instances.json`
- `pkg/catalog/data/components.json`

To update catalog data, replace the JSON files and run:

```sh
go test ./pkg/catalog
```

## Examples

Runnable examples are under `examples/`:

- `bare_vm`
- `l2bridge`
- `serialize_load`
- `drift_detection`

## Development

Run the test suite before sending changes:

```sh
gofmt -w .
go test ./...
```

Regenerate fixtures only when topology fixture behavior changes:

```sh
python testdata/generate_fixtures.py
go test ./...
```
